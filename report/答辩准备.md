# Lab 3 答辩准备（C 同学）

## 用最简单的话说明项目在做什么

CPU 正在执行内核代码时，可能突然遇到两类事情：时钟到了（中断），或当前指令本身有问题/是断点（异常）。CPU 不能直接丢掉当前状态，因此先跳到统一入口，把寄存器和返回位置装进一个“现场记录袋” `trapframe`。内核读 `scause` 判断发生了什么，处理完再把现场恢复，并用 `sret` 回到原来的代码。

本实验做的是这条“进入内核—保存现场—分辨原因—处理—恢复现场—返回”的闭环。时钟部分通过重复设置下一次 timer 事件实现周期中断；它还没有进程调度，因此 ticks 增长不代表进程发生了切换。

## 常见问题与回答

### 1. 什么是 Trap？

Trap 是 CPU 从当前执行流转入更高权限处理程序的统一机制。它包括异步中断和同步异常。处理结束后可以返回原执行流。

### 2. 中断和异常有什么区别？

中断一般与当前指令无关、异步发生，例如时钟中断；异常由当前正在执行的指令同步触发，例如 `ebreak` 或非法指令。两者都需要保存现场，但异常经常要修正 `sepc` 才能继续。

### 3. `trapframe` 是什么？它等于进程上下文吗？

它是一次 Trap 的现场记录，包含寄存器和 CSR 快照。本实验用它恢复被打断的内核执行流；没有据此切换到另一个进程，所以它不等于完整的进程调度/上下文切换实现。

### 4. 为什么 `RESTORE_ALL` 要先恢复 `sstatus`、`sepc`，而 `sp` 要最后恢复？

`sret` 需要正确的返回地址和特权状态，所以 `sepc/sstatus` 要在返回前写好。恢复其余值时都要用当前 `sp` 访问 Trap frame；如果提前恢复旧 `sp`，后续加载会读错地址，因此旧 `sp` 最后恢复。

### 5. 为什么用 `sret` 而不是 `ret`？

`ret` 只按普通函数调用的 `ra` 返回，不能恢复 S 态/特权级状态；`sret` 会结合 `sepc` 和 `sstatus` 执行特权返回。

### 6. `scause` 怎么区分中断和异常？

RV64 的 `scause` 最高位表示这是中断还是异常；其余位给出原因编号。`trap_dispatch()` 先按最高位分流，具体 handler 再识别原因号。

### 7. 为什么 timer handler 要调用 `clock_set_next_event()`？

一次 timer 到期后，必须预约下一次到期时间，才能形成周期中断。否则处理完当前中断后就不会持续得到下一次 timer 事件。

### 8. 为什么异常时 `epc` 有时加 2、有时加 4？

RISC-V 压缩指令是 16 位，普通指令是 32 位。低两位是 `11` 表示本实验遇到的是 32 位指令，推进 4；否则推进 2，避免返回后再次执行同一条触发异常的指令。

### 9. 初始页表为什么要有恒等映射和高半区映射？

开启 `satp` 后，CPU 还要从当前低端物理 PC 执行几条指令，因此需要恒等映射；跳到内核高半区后，内核又需要高虚拟地址到 DRAM 的映射。缺少任意一端都会在切换过程中取指失败。

### 10. 为什么页描述符数组也要从可分配内存里排除？

数组本身占用真实物理页来存每个 `struct Page`。若把这些页也放进空闲链表，分配器可能把保存自身元数据的内存重新分配给别的用途，导致页描述符被覆盖。

### 11. Best-Fit 和 First-Fit 有什么差异？

First-Fit 找到第一个足够大的空闲块就分配；Best-Fit 遍历空闲块，选择满足请求的最小块。Best-Fit 可能减少某些分配后剩余块的大小，但查找更慢，也不能消除外部碎片。本 Lab3 里 Best-Fit 是从 Lab2 合入的依赖。

### 12. timer ticks 增长是否代表发生了调度？

不是。ticks 只是计数器；调度还需要进程/线程状态、就绪队列、调度策略和上下文切换。本实验没有这些部分。

### 13. `make grade` 的测试在哪里运行？改动过测试吗？

`tools/inject.py` 把测试源复制到 `/tmp/lab3_grade` 临时树并注入测试调用，评分后使用临时工程。我们没有改评分 sentinel、分值或测试要求；只把 QEMU 启动方式改为 `-kernel`，让 OpenSBI 获得正确的内核跳转地址。
